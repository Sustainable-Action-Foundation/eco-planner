# i18n

[`locales.md`](../../locales.md) documents namespaces, key conventions, formatters and the client/server split. This file adds the rules and traps it does not cover. Swedish wording rules are in [domain-model.md](domain-model.md#swedish-terminology).

## Literal keys only
- A translation key always appears as a literal string inside `t("...")`. Never store keys in a map or variable and pass them to `t()`.
- For a label per enum value, build an inline record whose values are literal `t()` calls and index it: `{ [Enum.A]: t("ns:key_a"), [Enum.B]: t("ns:key_b") }[value]`.
- Why: the test locale renders keys, and the dead-key scan (`yarn check:locales`, `scripts/findDeadLocaleKeys.ts`) looks for literal usage. Dynamic keys are invisible to both.

## The server translator is bound to the request
- The server i18next instance (`src/lib/i18nServer.ts`) is one object per process, shared by every request.
- `serveTea()` loads the request's locale and namespaces and returns `getFixedT(locale)`. It never calls `changeLanguage` on the shared instance.
- Why: pages fetch their translator and then await the database before using it. Switching the shared language per request made overlapping requests render in each other's language: mixed-language pages for real users, and a test "flake" that looked like timing.
- Keep translators request-bound. When a server-rendered page shows the wrong language, suspect this class of bug before retrying.
- `tests/api/i18n-concurrency.spec.ts` guards it.

## New server keys need a restart
- The server reads `public/locales/{lng}/{ns}.json` from disk once per process. The client gets its translations from the server and picks changes up on reload.
- After a merge, pull or edit that adds keys, restart the dev server before concluding that a key does not resolve. Check whether the text is rendered on the server (`serveTea`) or the client (`useTranslation`) to know which side is stale.

## Tests render keys
Under `TEST_ENVIRONMENT=testing` the server defaults to the `cimode` locale and Playwright requests it too, so UI text renders as keys. Assert on keys, not prose. `src/lib/informativeCimodeT.ts` makes the key output carry enough to assert on.
